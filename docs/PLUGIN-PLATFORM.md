# LibreLayer plug-in platform

LibreLayer `.libreplugin` files are versioned JSON manifests installed from **Filter → Professional Studio → Local plug-in studio**. They stay in the current browser profile and can contribute declarative panels, local pixel filters, and image exporters. Installation never grants undeclared access and plug-ins cannot add arbitrary HTML, contact a network service, or read local files.

## Manifest and permissions

```json
{
  "format": "librelayer-plugin",
  "manifestVersion": 1,
  "id": "example.warm-grade",
  "name": "Warm Grade",
  "version": "1.0.0",
  "description": "A local color grade.",
  "hostApi": 1,
  "permissions": [
    "document.readPixels",
    "document.writePixels",
    "document.readComposite",
    "panel.show",
    "storage.settings",
    "export.download"
  ],
  "contributes": {
    "panel": {
      "title": "Warm Grade",
      "controls": [
        {
          "id": "amount",
          "label": "Amount",
          "kind": "slider",
          "default": 70,
          "min": 0,
          "max": 100
        },
        {
          "id": "protect",
          "label": "Protect highlights",
          "kind": "checkbox",
          "default": true
        }
      ]
    },
    "filters": [
      {
        "id": "warm",
        "label": "Warm locally",
        "cpuKernel": [0, 0, 0, 0, 1, 0, 0, 0, 0],
        "javascript": {
          "red": "clamp(r + 18)",
          "green": "g",
          "blue": "clamp(b - 8)"
        }
      }
    ],
    "exporters": [
      {
        "id": "preview",
        "label": "Web preview",
        "format": "webp",
        "extension": "webp",
        "quality": 0.82
      }
    ]
  }
}
```

Each capability requires its matching permissions. Unknown permissions, capabilities without permission, duplicate contribution ids, unsafe ranges, oversized manifests, incompatible host APIs, and malformed semantic versions fail before installation. A plug-in update replaces the same id only at an equal or newer version; downgrades require removing the installed version first. Up to 32 plug-ins, 24 controls, 24 filters, and 12 exporters per manifest are supported. Manifest files are limited to 1.5 MB.

## Safe JavaScript and WebAssembly

JavaScript filters use restricted channel expressions rather than evaluating arbitrary source. Supported variables are `r`, `g`, `b`, `a`, `x`, `y`, `width`, `height`, and normalized `amount`; supported functions are `abs`, `clamp`, `max`, `min`, `mix`, `pow`, and `round`. Property access, assignment, strings, loops, imports, global objects, and network APIs are rejected by the parser. Expressions are limited to 240 characters, 120 tokens, and 24 nesting levels.

Filter execution uses the same dedicated worker, copied pixel buffer, progress reporting, cancellation, 30-second watchdog, scratch staging, selection isolation, and transactional commit used by `.librefilter` filters. JavaScript expressions are interpreted inside that worker. WebAssembly receives no imports and uses the documented RGBA8 ABI in [FILTER-PLUGINS.md](FILTER-PLUGINS.md); a declared CPU kernel remains the deterministic fallback.

## Panels and exporters

Panels are generated by LibreLayer from slider, checkbox, color, and text declarations. They cannot inject HTML or run event code. Panel settings persist under the plug-in id in this browser profile. Exporters are bounded recipes for the built-in PNG, JPEG, or WebP encoders, so plug-ins never receive a file-system handle or write data directly. The user initiates every download.

Removing a plug-in removes its executable contributions but does not alter pixels already committed to documents. Plug-in edits create normal Undo/Redo history states.
